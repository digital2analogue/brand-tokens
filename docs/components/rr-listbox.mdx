## Examples

### Attribute picker

```html
<rr-listbox label="Attribute" value="income">
  <rr-chip slot="trigger" interactive>Income</rr-chip>
  <rr-option value="income">Income</rr-option>
  <rr-option value="tenure">Tenure</rr-option>
  <rr-option value="score">Credit score</rr-option>
</rr-listbox>
```

<rr-listbox label="Attribute">

## Accessibility

- **WAI-ARIA pattern:** [www.w3.org/WAI/ARIA/apg/patterns/listbox/](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)
- **Focusable:** no
- **Keyboard:** Enter, Space, or click on the trigger toggles the listbox; ArrowDown or ArrowUp on the trigger opens it focused on the current value; ArrowDown/ArrowUp move through enabled options and wrap; Home/End jump to the ends; Enter or Space chooses the focused option, closes, and returns focus to the trigger; Escape closes and returns focus to the trigger; Tab closes and moves on
- **WCAG:** 1.4.3 Contrast (Minimum), 1.4.11 Non-text Contrast, 2.1.1 Keyboard, 2.4.3 Focus Order, 4.1.2 Name, Role, Value

**Rules**

- The slotted trigger receives aria-haspopup=listbox and live aria-expanded automatically
- Every option carries aria-selected, true or false — a listbox whose unchosen options are silent reads as a list of buttons
- Disabled options are skipped by keyboard navigation and are inert to clicks
- Focus returns to the trigger on Escape and on selection
- The selected option is marked by a check glyph as well as accent colour, so selection never depends on colour alone

## Guardrails

**System rules** — how each is enforced in parentheses; `manual` means nothing checks it for you.

- `hard-1` _(lint)_ — No hardcoded colors — use var(--color-*) custom properties
- `hard-5` _(manual)_ — Accent green (foreground.action, foreground.accent, background.action, background.accent) is never resting text or decoration — it signals interactivity or intentional emphasis only
- `hard-6` _(gate)_ — All text must meet WCAG AA contrast (4.5:1) against its background — all pairings in the system already do; do not introduce new ones without checking
- `hard-9` _(lint)_ — Never use primitive tokens (color.green.*, space.*, font.size.*) in UI code — always go through the semantic layer

**Using rr-listbox**

- Listbox vs menu is a question of what the control DOES, not how it looks. A menu fires commands and nothing latches; a listbox sets a value and the chosen option stays marked. Using rr-menu for selection is the wrong ARIA role, not merely a missing prop — role=menuitem has no selected state at all.
- Listbox vs rr-select is a question of option content. rr-select wraps a native <select> and emits native <option>, which renders text and nothing else at any level of CSS effort — that constraint is the platform's, and it is what makes rr-select form-associated. Reach for rr-listbox only when an option needs an icon, a swatch or a second line; reach for rr-select whenever plain text will do, because it participates in forms for free.
- The trigger is an rr-chip and the menu trigger is an rr-button. Those two silhouettes — radius.sm against radius.default — are the only cue distinguishing them at rest, since both are 'click a thing, a panel appears'. A chip is right here because what the trigger displays IS the current value. Use the chip's empty mode while nothing is chosen.
- Never let the trigger declare aria-haspopup or aria-expanded itself: the listbox stamps both onto whatever sits in the trigger slot, exactly as rr-menu does. That is what keeps one chip correct as a filter and as a trigger.
- value is OWNED by the listbox and settable to control it — unlike rr-chip[pressed] and rr-tab[selected], which are controlled only. The line is whether the component can see the whole state: a listbox holds exactly one value and is the container for it, while a chip is one control in a filter row whose state is the set, which no single chip can know.
- Opening focuses the CURRENT value, not the first option — reopening a listbox should put you where you already are. A list that always opens at the top makes the user re-find their own choice every time.
- Always set label; it names the popup for assistive tech. The popup positions with CSS below the trigger (no portal), so keep the listbox outside overflow:hidden ancestors.
