## Properties

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `string` | `` | Value reported in rr-listbox's rr-listbox-select event when this option is chosen. |
| `selected` | `boolean` | `false` | Whether this option is the listbox's current value. Set by the parent rr-listbox. |

## Accessibility

- **WAI-ARIA pattern:** [www.w3.org/WAI/ARIA/apg/patterns/listbox/](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)
- **Focusable:** yes
- **Keyboard:** Options are focused programmatically by rr-listbox during keyboard navigation (tabindex -1); Enter or Space on the focused option chooses it
- **WCAG:** 1.4.3 Contrast (Minimum), 1.4.11 Non-text Contrast, 2.1.1 Keyboard, 2.4.7 Focus Visible, 4.1.2 Name, Role, Value

**Rules**

- aria-selected is present on every option, true or false, not only on the chosen one
- Disabled options carry aria-disabled and are inert to both click and keyboard
- Selection is carried by a check glyph as well as accent colour — never by colour alone
- The focused row shows an inset focus ring, because options are focused programmatically inside an overlay
- Label text (foreground.default on background.alt, 9.9:1) and description text (foreground.muted, 5.1:1) both clear WCAG AA; the selected accent pairs foreground.accent-green on background.accent-green at 9.7:1

## Guardrails

**System rules** — how each is enforced in parentheses; `manual` means nothing checks it for you.

- `hard-1` _(lint)_ — No hardcoded colors — use var(--color-*) custom properties
- `hard-5` _(manual)_ — Accent green (foreground.action, foreground.accent, background.action, background.accent) is never resting text or decoration — it signals interactivity or intentional emphasis only
- `hard-6` _(gate)_ — All text must meet WCAG AA contrast (4.5:1) against its background — all pairings in the system already do; do not introduce new ones without checking
- `hard-9` _(lint)_ — Never use primitive tokens (color.green.*, space.*, font.size.*) in UI code — always go through the semantic layer
- `hard-10` _(lint)_ — Motion must respect `prefers-reduced-motion` (WCAG 2.3.3). The built brand CSS zeroes `--motion-duration-*` under `reduce`, so token-driven transitions stop automatically — never hardcode a transition/animation duration that bypasses the tokens. Any infinite animation (spin, shimmer, pulse) cannot be reached by the token override and MUST carry its own `@media (prefers-reduced-motion: reduce)` guard that stops or damps it

**Using rr-option**

- selected is set BY the parent rr-listbox from its value — do not drive it by hand. Setting it directly on an option desynchronises the two and produces a listbox with two checks or none.
- The check mark keeps its box when the option is unselected (visibility, not display), so rows do not shift as the selection moves down the list.
- A description is a second line of meaning, not a place for overflow. If the label needs the description to make sense, the label is wrong.
- Use leading for a swatch or category glyph — the channel a native <option> cannot provide, and the reason this family exists next to rr-select.
