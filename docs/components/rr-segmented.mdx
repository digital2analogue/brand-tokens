## Overview

`rr-segmented` sets a field's value from two or three choices that are all
visible at rest. It is the same job a listbox does — commit one value — traded
differently: it spends screen space so choosing costs a single tap instead of a
click to open and a click to pick.

That trade stops paying past three options. When the choices no longer fit on a
line, they belong behind a click: reach for a listbox instead of shrinking the
labels.

It sits in the badge/chip family and is told apart from its neighbours by what
it does with a value, not by whether it can be clicked:

| | what it is |
|---|---|
| **Badge** | state the system reports; you cannot influence it |
| **Chip** | a discrete thing — a category, a filter, a value someone chose |
| **Segmented** | a field whose two or three choices are all visible at rest |
| **Listbox** | a field whose choices are behind a click |
| **Menu** | commands; nothing latches |

The tell for this one is `role="radiogroup"` / `role="radio"`, exactly one
choice checked, and a value that survives the interaction. A menu latches
nothing; a row of chips names things rather than setting one of them.

## Accessibility

- **WAI-ARIA pattern:** [www.w3.org/WAI/ARIA/apg/patterns/radio/](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)
- **Focusable:** no
- **Keyboard:** Tab enters the group once — the chosen segment is the tab stop, or the first enabled one when nothing is chosen; ArrowRight / ArrowDown move to the next enabled segment and select it (wraps); ArrowLeft / ArrowUp move to the previous enabled segment and select it (wraps); Home selects the first enabled segment, End the last; With nothing chosen, either arrow direction commits the first segment
- **WCAG:** 1.4.3 Contrast (Minimum), 1.4.11 Non-text Contrast, 2.1.1 Keyboard, 2.4.7 Focus Visible, 4.1.2 Name, Role, Value

**Rules**

- label is required so the radiogroup has an accessible name via aria-label.
- Selection follows focus, per the WAI-ARIA radio group pattern: arrows both move and check. Roving tabindex keeps the whole group to one tab stop.
- The indicator is a non-text state indicator under SC 1.4.11: it carries a border at color-border-default (3:1+ on the track) as well as its fill, so the chosen segment is not signalled by fill alone.
- Tone is never the only channel — the chosen segment is also the one the pill sits under and the only one with aria-checked=true.
- Tinted pills are color-mix composites the contrast gate cannot declare as a pairing. Measured on base dark against their tone foreground: success 6.9:1, danger 5.5:1, warning 7.9:1, info 8.0:1, neutral 9.9:1 — all AA.

## Guardrails

**System rules** — how each is enforced in parentheses; `manual` means nothing checks it for you.

- `hard-1` _(lint)_ — No hardcoded colors — use var(--color-*) custom properties
- `hard-6` _(gate)_ — All text must meet WCAG AA contrast (4.5:1) against its background — all pairings in the system already do; do not introduce new ones without checking
- `hard-9` _(lint)_ — Never use primitive tokens (color.green.*, space.*, font.size.*) in UI code — always go through the semantic layer
- `hard-10` _(lint)_ — Motion must respect `prefers-reduced-motion` (WCAG 2.3.3). The built brand CSS zeroes `--motion-duration-*` under `reduce`, so token-driven transitions stop automatically — never hardcode a transition/animation duration that bypasses the tokens. Any infinite animation (spin, shimmer, pulse) cannot be reached by the token override and MUST carry its own `@media (prefers-reduced-motion: reduce)` guard that stops or damps it

**Using rr-segmented**

- Use it at two or three choices. Past that the control stops fitting and the choice belongs behind a click — reach for a listbox instead. This is the same job as a listbox (set a field's value), traded for screen space.
- It is a field, not a row of buttons and not a menu: exactly one choice is checked and the value survives the interaction. A menu latches nothing; a chip group names things rather than setting one value.
- Leave value empty for an unanswered field — no indicator is drawn at all, so a draft row cannot be mistaken for one that chose the first option.
- Segments are equal-width by construction (one 1fr grid column each, so every segment is as wide as the widest label), which is what lets the indicator be placed arithmetically instead of measured. Labels of very different lengths will make the whole control wide; shorten the labels rather than fighting the layout.
- The indicator owns all the chrome — fill, border, shadow. Never give a segment its own box: two boxed segments read as two adjacent buttons rather than one field.
- Set tone on a segment to colour-code the chosen value; the indicator picks up a 12% tint of the same role. That is what makes an outcome scannable down a column of many rows.
- The pill slides on motion-easing-move. An overshoot curve would read better — the pill should feel moved rather than recoloured — but the system has no spring easing yet (#232).

## Usage

**Do** leave `value` empty for a field nobody has answered yet. No indicator is
drawn at all, which is the point: a draft row must not look like it chose the
first option.

**Do** set `tone` on a segment when the value itself has a semantic reading — an
outcome, a status. The indicator picks up a 12% tint of the same role, which is
what makes the chosen value scannable down a column of many rows rather than
something you have to read.

**Don't** give a segment chrome of its own. The indicator owns the fill, the
border and the shadow; segments carry label colour only. Two segments that each
drew a box read as two adjacent buttons instead of one field with one value —
that difference is the entire reason this is a component rather than a chip
group.

**Don't** reach for it as a toolbar. Nothing here fires a command; every
interaction leaves a value behind. If pressing an option should *do* something
rather than *be* something, you want buttons or a menu.

**Don't** hand it labels of wildly different lengths. Segments are equal-width
by construction (`flex: 1 1 0`), which is what lets the indicator be placed
arithmetically instead of measured — a one-word option beside a five-word one
will look loose. Shorten the labels.

### Known downgrade

The pill slides on `--motion-easing-move`. An overshoot curve would read better
here — the pill should feel like a physical thing being moved, not a colour
being changed — but the system has no spring easing to point at yet. Tracked in
[#232](https://github.com/digital2analogue/parsimony/issues/232).
